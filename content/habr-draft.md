# Каска есть? Open-source детектор СИЗ с контролем опасных зон за выходные

> Черновик для Habr. Ссылки `[GITHUB_URL]` / `[HF_SPACE_URL]` подставить при публикации.
> Метрики — из реального прогона `eval.py`, не из головы.

Детекция касок на видео с камеры — самый растиражированный YOLO-туториал в интернете. На
GitHub десятки репозиториев «helmet detection», и почти все заканчиваются на «обучил YOLO,
нарисовал рамки». Как инженерный артефакт это говорит мало: рамка вокруг головы — не отчёт,
который нужен инженеру по охране труда.

Я собрал проект, который доводит задачу до сигнала, на который можно реагировать:
**кто без каски и находится ли он в опасной зоне.** Делюсь стеком, числами и — отдельно —
честным разбором, почему это open-source-проект, а не стартап.

## Сразу про честность: почему не продукт

Промышленная видеоаналитика СИЗ в РФ — занятый рынок. VizorLabs, NtechLab, VisionLabs,
Cognitive Pilot; плюс «1С:Производственная безопасность» заходит видеоаналитикой через ERP в
каждый завод. Сверху — регуляторика: 187-ФЗ (КИИ), ФСТЭК-сертификация для интеграции со СКУД,
44/223-ФЗ-тендеры. Соло-разработчик сюда не входит — это структурная стена, а не недоработка.

Поэтому проект честно позиционируется как **open-source learning artifact**: показать полный
CV-цикл (данные → дообучение → оценка → деплой) и понимание ниши, а не «убийцу Intenseye».

## Чем это отличается от «ещё одного YOLO»

Три вещи превращают детектор в инструмент:

1. **Геофенсинг.** Детекции сопоставляются с заданными оператором полигонами опасных зон
   (координаты нормализованы — зона переживает ресайз кадра). Непокрытая голова *в зоне у
   пресса* — это `CRITICAL`; та же голова в проходе — `WARNING` уровня площадки. Чистая
   геометрия, покрыта unit-тестами.
2. **Мультикамерный трекинг.** ByteTrack даёт стабильные ID между кадрами — нарушение
   становится событием на человека, а не шумом на каждом кадре.
3. **Честная оценка.** Per-class mAP генерируется скриптом и вставляется в README дословно,
   с показом ошибок модели.

Архитектура держит модельный слой тонким, а всю «логику суждения» — в тестируемом слое
геофенсинга:

```
кадр ─▶ YOLOv11 ─▶ детекции ─▶ geofencing.evaluate() ─▶ нарушения ─▶ оверлей/отчёт
                                      ▲
                          зоны (configs/zones.yaml)
```

## Данные и обучение

Датасет — `keremberke/hard-hat-detection` (экспорт Hard Hat Workers с Roboflow), 2 класса:
`hardhat` и `no-hardhat`. Класс `no-hardhat` — ровно тот сигнал нарушения, на который завязан
геофенсинг. Загрузка без API-ключа: качаем COCO-зипы с Hugging Face и конвертируем в YOLO.

- Train / val / test: 13 782 / 3 962 / 2 001 изображений
- Модель: YOLO11s, 80 эпох, 640px
- Железо: одна RTX 3080 (10 ГБ), батч 16

## Результаты

| Класс | mAP@50 | mAP@50-95 |
|---|---|---|
| hardhat | 0.942 | 0.557 |
| no-hardhat | 0.933 | 0.645 |
| **overall** | **0.937** | **0.601** |

Precision 0.91, Recall 0.91. Инференс — **2.9 мс/кадр** (3.7 мс end-to-end) на RTX 3080,
то есть реальный real-time. Профиль под edge (Jetson Orin Nano) — следующий шаг.

## Где модель ошибается

- Бэкбон обучен на строительных кадрах; доменный сдвиг к тяжёлой промышленности (дым, блики,
  дистанция) роняет recall. Per-class числа выше показывают, где именно.
- Связка «каска↔человек» использует дешёвую эвристику горизонтального перекрытия, не позу —
  на сильных перекрытиях может ошибаться. Это задокументировано осознанно.
- Это не КИИ-система: без интеграции со СКУД, без ФСТЭК-сертификации, без журнала аудита.
